# Complete AOSP & LineageOS Bringup and Troubleshooting Guide

This guide details how to take the trees generated by **Universal Firmware Extractor** and achieve a successful, bootable build of LineageOS or AOSP for your target device.

---

## 1. Directory Structure of Generated Trees

When tree generation completes, your sources are organized according to standard Android build system conventions:

```text
android_source/
├── device/<brand>/<codename>/
│   ├── AndroidProducts.mk       # Lunch target declarations
│   ├── BoardConfig.mk           # Hardware flags, kernel setup, super dynamic partitions
│   ├── device.mk                # Product copy files, init scripts, HAL packages
│   ├── lineage_<codename>.mk    # LineageOS specific product definition
│   ├── aosp_<codename>.mk       # Generic AOSP product definition
│   ├── proprietary-files.txt    # List of extracted proprietary vendor blobs
│   ├── extract-files.sh         # Script to re-extract blobs from device/dump
│   ├── setup-makefiles.sh       # Script to generate vendor makefiles
│   ├── rootdir/etc/             # Extracted fstab and init.target.rc scripts
│   ├── prebuilt/                # Prebuilt kernel, dtb.img, dtbo.img
│   └── sepolicy/vendor/         # Vendor SELinux policy rules
└── vendor/<brand>/<codename>/
    ├── Android.mk               # Vendor build rules
    ├── Android.bp               # Soong namespace definition
    ├── <codename>-vendor.mk     # PRODUCT_COPY_FILES for proprietary blobs
    └── proprietary/             # Extracted vendor binaries, libraries, firmware
```

## 2. Setting Up the ROM Build Environment

1. **Initialize the LineageOS / AOSP source tree:**
   ```bash
   mkdir -p ~/android/lineage && cd ~/android/lineage
   repo init -u https://github.com/LineageOS/android.git -b lineage-21.0 --git-lfs
   repo sync -c -j$(nproc --all) --force-sync --no-clone-bundle --no-tags
   ```

2. **Place your generated trees:**
   - Clone or copy your `device/<brand>/<codename>` to `device/<brand>/<codename>/`.
   - Clone or copy your `vendor/<brand>/<codename>` to `vendor/<brand>/<codename>/`.

3. **Verify LineageOS build tools (`extract-utils`):**
   ```bash
   git clone https://github.com/LineageOS/android_tools_extract-utils.git tools/extract-utils
   ```

## 3. Dynamic Partition Configuration & Sizing

Modern Android devices (Android 10+) use **Virtual A/B** and **Dynamic Partitions** inside `super.img`.

In `BoardConfig.mk`:
```makefile
# Define super partition size (match stock partition size in bytes)
BOARD_SUPER_PARTITION_SIZE := 9126805504

# Define group name (conventionally <brand>_dynamic_partitions or qti_dynamic_partitions)
BOARD_SUPER_PARTITION_GROUPS := mybrand_dynamic_partitions

# Max group size (typically BOARD_SUPER_PARTITION_SIZE - 4MB margin)
BOARD_MYBRAND_DYNAMIC_PARTITIONS_SIZE := 9122611200

# Specify every dynamic partition extracted from your dump
BOARD_MYBRAND_DYNAMIC_PARTITIONS_PARTITION_LIST := \
    system \
    vendor \
    product \
    system_ext \
    odm
```

> **Troubleshooting Sizing Issues:**
> If you encounter `No space left on device` or `super partition overflow` during `make superimage`:
> 1. Increase `BOARD_<GROUP>_DYNAMIC_PARTITIONS_SIZE` if physical super partition allows.
> 2. Strip unnecessary prebuilt debug symbols and non-essential vendor apps.

## 4. Fstab and First Stage Mount Verification

First-stage mount failures are the #1 cause of early kernel panics and bootloops before `init` reaches logcat.

In `device/<brand>/<codename>/rootdir/etc/fstab.<hardware>`:
1. Verify the filesystem type matches your dump:
   - For EROFS: `erofs ro,barrier=1,discard wait,logical,first_stage_mount`
   - For EXT4: `ext4 ro,barrier=1,discard wait,logical,first_stage_mount`
2. Encryption flags in `/data`:
   - If stock uses `fileencryption=aes-256-xts:aes-256-cts:v2+inlinecrypt_optimized+wrappedkey_v0`, ensure kernel supports hardware-wrapped keys.
   - For initial testing, you can change to standard `fileencryption=aes-256-xts:aes-256-cts:v2` or `encryptable`.

## 5. Prebuilt Kernel & DTB Integration

If bringing up an initial ROM without building the kernel inline from source, use the prebuilt kernel extracted by `Firmware_extractor`:

In `BoardConfig.mk`:
```makefile
TARGET_PREBUILT_KERNEL := $(DEVICE_PATH)/prebuilt/kernel
TARGET_PREBUILT_DTB := $(DEVICE_PATH)/prebuilt/dtb.img
BOARD_PREBUILT_DTBOIMAGE := $(DEVICE_PATH)/prebuilt/dtbo.img
BOARD_INCLUDE_DTB_IN_BOOTIMG := true
BOARD_BOOT_HEADER_VERSION := 2
BOARD_KERNEL_PAGESIZE := 4096
```

## 6. Critical Proprietary Blobs Checklist

Ensure the following critical HALs are present in `proprietary-files.txt` and verified inside `vendor/<brand>/<codename>/proprietary/`:

| Subsystem | Critical Blobs / HALs | Purpose |
|---|---|---|
| **Graphics / Display** | `hwcomposer.*.so`, `gralloc.*.so`, `libdrm*.so` | SurfaceFlinger rendering and display pipeline |
| **Radio / Telephony** | `libril*.so`, `rild`, vendor telephony services | SIM detection, cellular connectivity, mobile data |
| **Power & Health** | `android.hardware.power-service`, `health-service` | Charging control, battery stats, sleep state |
| **Sensors & Audio** | `audio.primary.*.so`, `audio_policy_configuration.xml` | Mic, speaker, sound routing, sensor hub |
| **Vendor Firmware** | `/vendor/firmware/` (`adreno*`, `modem*`, `wifi*`) | Hardware DSP and baseband initialization |

## 7. SELinux Denials & Permissive Troubleshooting

During initial device bringup:
1. In `BoardConfig.mk`, set permissive mode for testing:
   ```makefile
   BOARD_KERNEL_CMDLINE += androidboot.selinux=permissive
   ```
2. Once booted, capture denials:
   ```bash
   adb shell dmesg | grep "avc: denied" > avc_denials.txt
   ```
3. Generate policy rules using `audit2allow`:
   ```bash
   audit2allow -i avc_denials.txt -p $OUT/obj/ETC/sepolicy_intermediates/sepolicy
   ```
4. Place the generated rules under `device/<brand>/<codename>/sepolicy/vendor/*.te`.

---

## 8. Starting the Build

```bash
source build/envsetup.sh
lunch lineage_<codename>-userdebug
mka bacon -j$(nproc --all)
```

Flash the generated zip from `out/target/product/<codename>/lineage-*.zip` via recovery.
